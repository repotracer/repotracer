What was wrong

The old text defined “broad” mostly as multi-component work and even used a request-lifecycle example as a local case. The subscription task explicitly required every caller plus exported configuration and process APIs, but that blast radius did not win the classification. Sol’s zero Scout calls were consistent with the installed rule.

The first correction swung too far. It sent all six broad cases to Scout, but it also sent the small json-version task to Scout in both repeats. That failed attempt stays in the raw results. The final wording adds a concrete local path: one targeted lookup for a likely single command, function, or file, followed by Scout only if the surface expands.

The patches were reviewed after the behavioral checks. Both local implementations satisfy the requested contract; the baseline is marginally cleaner because it reuses a version local and asserts empty stderr, while the RepoTracer patch adds no functional defect. The broad candidate changes only subscription.rs, resets one deadline from non-whitespace stdout or stderr, retains the process ID after direct-child exit, kills the descendant tree, and tests both a run longer than the idle interval and a delayed descendant. No quality regression was found.

The local pair observed 16.6% lower cost and 3.6% lower wall time. The corrected broad run was 49.9% cheaper and 33.6% faster than the retained baseline median. One local pair and one new broad candidate are enough to reject obvious routing regressions, not enough to claim release-wide effect sizes.

Why no hook

Codex PreToolUse hooks can block or rewrite a known tool call. They do not know whether a natural-language task is semantically broad. Enforcing the route would still require a classifier before every prompt. The retained Luna pre-classifier reached only 50% broad-task recall, while adding a model call to every task. That is more machinery with worse evidence than the corrected contract.

The failure was not “Sol ignored the right rule.” The rule was wrong. Fixing that source is both smaller and more reliable than building stateful hook policy around another uncertain classifier.

Scout default and configuration

  • The selected fast Scout remains gpt-5.6-luna at medium reasoning.
  • The default service tier remains default. model.service_tier stays configurable; fast and priority map to the priority request path.
  • The priority plumbing test passes. In the retained nine-pair provider logs, every successful call still reported actual_service_tier=default. Another large tier matrix would not answer a product question until the provider exposes a real tier difference.
