Benchmark architecture / decision required

Build MAH-SWE, then change Scout.

Use two separate evidence lanes: a public repository benchmark for external capability, and MAH-SWE for our real multi-round work. Do not tune tools, prompts, or routing against today’s small routing set.

decision

Adopt the version 3 protocol now. Use DeepSWE as the primary public lane, SWE-Interact only for continuity questions, and MAH-SWE as the private real-work lane. Approve the proposed release gate before researching Scout search tools.

01 / formalDeepSWE first

Original tasks, functional verifiers, repeated rollouts, and public artifacts. Keep SWE-bench Verified as a legacy diagnostic, not a headline.

02 / real workMAH-SWE

Original or private tasks with ordered follow-up turns, one persistent session, hidden verification, and blind weighted review.

03 / promotionNo one-run wins

Require paired repeated evidence and uncertainty bounds. A cheap result that loses required behavior fails.

01Why this split

No single benchmark answers all three questions. Public tasks give comparability. Private real work gives relevance. Multi-round tasks expose continuity and recovery failures that a one-shot patch benchmark cannot.

02One benchmark run, end to end

01
Author the task

The task owner records the source repository and base commit, writes natural user turns, preregisters a 100-point rubric, and supplies behavioral verification. Solver prompts never contain expected paths, rubric text, or verifier details.

02
Freeze the plan

repotracer-bench validates every task, hashes the ordered prompts, creates baseline and RepoTracer pairs, randomizes pair order from the study ID, and alternates which arm runs first. Release mode refuses fewer than 30 tasks, fewer than three repeats, or any unapproved task.

03
Run each arm

Both arms start from the same commit, model, reasoning level, environment, and byte-identical turns. One solver thread and one worktree persist through every round. The treatment adds only RepoTracer and its routing instructions.

04
Capture real economics

The coordinator stores patch, repository state, verifier output, final replies, and trajectories. Cost comes from provider billing for the main solver, every child agent, and every Scout request. Wall time is measured around the complete trial, not a single model call.

05
Grade blind

Behavioral verification runs first. The planner emits opaque review IDs and forms that omit arm, routing, cost, latency, and repeat. A reviewer scores each criterion from the sanitized artifact bundle, records evidence, marks required items, and locks the review before unblinding.

06
Compare pairs

Analysis reports task-level paired quality, complete cost, and wall-time deltas. A 95% task-cluster bootstrap resamples tasks while keeping every repeat from a task together. Losing trials remain in the record.

Failure rule: provider, harness, or verifier infrastructure failures invalidate and resample both arms. Agent timeout, context exhaustion, bad patch, missed requirement, or failed verification counts as model failure. This keeps infrastructure noise out without forgiving agent behavior.

03Proposed release gate

1 / QualityWeighted task score plus required itemsNo new security, data-loss, or required-behavior failure. The 95% lower bound of the paired quality delta must be at least −5 points.A 60% saving is not useful if Scout makes Sol ship the wrong change.
2 / CostComplete provider USD: solver + children + ScoutTarget at least 60% median reduction; the 95% lower bound must remain above 0%.Provider billing handles cache and model-price differences that raw token totals hide.
3 / TimeComplete trial wall timeThe 95% upper bound of the paired regression must not exceed +20%.Scout may add a short handoff, but must not turn search savings into a slower product.
Evidence floorIndependent tasks and repeatsAt least 30 tasks and three randomized repeats per arm.One task can diagnose a mechanism. It cannot justify a release claim.

These are promotion thresholds, not claims about current performance. Existing RepoTracer studies remain diagnostics because they use too few independent tasks.

05Open risks and next decision

  • Corpus gap. MAH-SWE has one task. Twenty-nine more independent, verifier-backed tasks are required before release-grade conclusions.
  • Reviewer leakage. The forms are blind, but the coordinator must copy sanitized bundles by review ID and keep the manifest mapping private until scores lock.
  • Private-task bias. MAH-SWE can overfit to our repositories. DeepSWE remains separate so a local gain cannot masquerade as general repository capability.
  • Cost of evidence. The minimum release matrix is 180 complete trials before external formal runs. Use pilots for harness debugging, never for promotion claims.
  • Research limit. The Deep Research bridge daemon was unavailable. This decision uses direct reads of primary papers, repositories, and local benchmark artifacts instead.
Decision requested: approve this architecture and the proposed gates, or change them now. If approved, the next iteration compares large-repository search tools against Scout’s read-only, citation-bearing, low-cost boundary. No tool integration happens before that report.
